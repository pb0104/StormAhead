Disaster Ops Agent System

An AI operations center for emergency management. Specialist agents each watch one part of a disaster: roads, power, weather, people, communications. A shared layer combines what they find into one verified picture, then drafts resource moves, alerts and briefs. A person approves every action.

    Across the disaster timeline

    Before

    Prepare

    • Predict roads and critical sites at risk
    • Pre-position crews, fuel, water
    • Plan evacuation routes and spot bottlenecks
    • Send targeted, multilingual warnings
    During

    Respond

    • Keep one verified shared picture
    • Find cut-off and quiet areas
    • Match needs to resources along passable routes
    • Shift handoffs and situation reports
    After

    Recover

    • Which roads to clear first (people reconnected per mile)
    • Power restoration priorities
    • Track unmet needs by area
    • After-action report into memory

    A browser globe that stacks dozens of public feeds, with a voice agent and MCP server.

    Take
    • One module per feed, catalogued in DATA_SOURCES.md
    • Server proxy that hides keys and caches
    • Agent tools grouped as Direct, Annotate, Interrogate, Operate
    • Replay scenes (it has a Nepal flood replay)
    • Shareable view links

    • 3D globe and tokens (MapLibre + deck.gl instead)
    • Surveillance-style layers

    Open models & frameworks

    Toolkit

    • Imagery data: Maxar Open Data (CC BY-NC 4.0, STAC catalog, Helene pre/post), NOAA aerial, Sentinel
    • Imagery models: Prithvi flood (Apache-2.0), TerraMind, xView2 damage, GeoChat
    • Imagery tools: leafmap, TiTiler, rasterio, pystac
    • Text: CrisisTransformers; a frontier multimodal LLM for most tasks
    • Audio: Whisper / faster-whisper
    • Routing: OSMnx, OSRM, Valhalla
    • Agents: LangGraph, CrewAI, Claude Agent SDK, MCP
    • Map: MapLibre, deck.gl
    • Datasets: CrisisMMD, HumAID, xBD, FloodNet, RescueNet

    Product framing

    Users

    • FEMA regional staff
    • NC Emergency Management, 24-Hour Watch
    • County emergency managers

    Problem

    • Too much data across separate tools
    • Too few analysts
    • Slow, unverified situational awareness
    • Knowledge lost between shifts

    Measures

    • Time from first signal to verified decision
    • Critical sites flagged before failure
    • Resources sent on routes that were passable
    • Analyst hours saved

    Guardrails

    • A person approves every action
    • Area level only, no tracking of individuals
    • Confidence and evidence on every item
    • Sources named on every item

    Shape for a weekend

    Approach

    • Show every layer thinly; build two or three agents in depth
    • Replay Hurricane Helene in western NC so the product never depends on live feeds
    • One shared event format so agents can be built in parallel

    Gaps to plan around

    • 911 and live power/cell data aren't public: simulate and say so
    • Imagery arrives a day or more late and clouds block it: social posts and gauges cover the first hours
    • Apply early for DriveNC, Flood Hub keys

    Still open

    • Which two or three agents go deep?
    • Which combined finding is the pitch moment?
